Edict（三省六部）多 Agent 编排系统

用 1300 年前的唐朝分权制度，设计现代 AI Agent 协作架构 · 2026-06-10

一句话：Edict 是一个基于唐代"三省六部制"的 AI 多 Agent 协作框架，用中书省的规划权、门下省的封驳权、尚书省的派发权、六部的执行权，形成制衡闭环——古人比现代 AI 框架更懂分权制衡。

Edict 由开发者 cft0808 创建，基于 OpenClaw 运行时，前端 React 18 + TypeScript + Vite + Zustand，后端 Python stdlib only。项目以 MIT 许可证开源，曾登顶 GitHub 全球趋势榜。

它的核心创新不是技术——而是组织架构。Edict 把 AI Agent 当作"朝廷官员"，用唐朝的三省六部制来分配权力、管控流程、防止滥用。

二、为什么这对你重要？

如果你在教练/教学场景中涉及以下问题，Edict 是最好的教学案例：

  • 多 Agent 协作：当多个 AI 一起工作，谁来管？怎么分任务？谁审核？
  • AI 治理：如何防止 AI 乱执行？谁来否决错误的决策？
  • 制度 vs 技术：好的组织架构设计比技术实现更重要——这个理念对企业数字员工转型和二代传承都有启发
  • 教育场景：三省六部的历史映射 + AI Agent 的现代结合，是极好的跨学科教学素材
教练视角： Edict 展示了一个真理——AI 时代最稀缺的不是技术能力，而是组织设计能力。用好分权制衡、审核封驳、责任闭环这些制度智慧，比写多少行代码都重要。

四、旨意生命周期——从下旨到归档

一个任务（旨意）从创建到完成，经过 7 个阶段，每个阶段由不同的 Agent 负责，形成完整闭环：

①用户下旨
→
②太子分拣
→
③中书规划
→
④门下审议
→
⑤尚书派发
→
⑥六部执行
→
⑦回奏归档

关键设计点：

  • 封驳机制：门下省在④阶段可以打回中书省重做——这是整个系统的核心制衡节点
  • 单向依赖链：太子→中书→门下→尚书→六部，不可越级
  • 六部隔离：六部之间不能直接通信，防止私下串通
  • 尚书枢纽：尚书省是唯一能联系全部六部的节点
  • 中断机制：任何阶段用户可叫停；封驳打回后可重新规划
💡 教练思考

这 7 个阶段其实是一个完整的 PDCA 循环（Plan→Do→Check→Act）。中书省是 Plan，门下省是 Check，尚书省+六部是 Do，回奏是 Act。企业数字化转型中，这个流程同样适用——先审批后执行、执行可追溯、结果可复盘。

五、权限矩阵——制度的核心

Edict 最精妙的设计是权限矩阵。每个 Agent 只能与特定的 Agent 通信，不能越级、不能串通：

Agent可联系不可联系
太子中书省门下省、尚书省、六部
中书省门下省、尚书省太子、六部
门下省中书省、尚书省太子、六部
尚书省三省 + 全部六部太子
六部各司尚书省彼此之间不能直接通信
早朝官仅仪式/资讯不参与政务流程

设计原则：

  • 单向依赖链，信息流从用户逐级向下
  • 门下省是唯一的"反向通道"——可以把计划打回中书省
  • 六部隔离——没有尚书省协调，六部之间不能串通
  • 制度信用比效率更重要——多一步审核，少一个错误

七、教练视角：三省六部的三个启发

🏢 启发一：制度设计 > 技术选型

Edict 的创始人没有追求"更先进的算法"，而是从历史中找到了答案。这给企业数字员工转型的启示是：先设计好组织架构和流程制度，再选工具。很多 AI 转型失败不是因为技术不够好，而是流程没想清楚——谁来发起？谁来审批？谁来执行？谁来验收？

🧠 启发二：封驳权是 AI 治理的核心

在 AI 越来越强大的时代，谁来否决 AI 的决定是一个关键问题。Edict 的门下省封驳权提供了一个思路：在 AI 执行的流程中嵌入一个独立的审核节点，专门负责"挑毛病"。这对任何企业部署 AI 都有借鉴意义。

📚 启发三：跨学科教学的好素材

三省六部制 + AI Agent 的组合，是二代传承教育中历史 × 技术 × 管理的绝佳案例。学生可以：

  • 从历史角度理解分权制衡的起源
  • 从技术角度理解 Agent 协作的原理
  • 从管理角度理解组织设计的核心要素
